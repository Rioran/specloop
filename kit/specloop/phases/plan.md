## Phase: plan

Read the specification at `{spec}` and the code it touches. Do not modify source code in this phase.

Write `{run_dir}/plan.md` containing:
1. A short restatement of the goal and acceptance criteria taken from the spec.
2. Open questions or assumptions (make a reasonable assumption rather than stopping to ask).
3. A checklist of implementation steps (`- [ ] ...`), each naming the files involved.
4. The unit tests that will prove the acceptance criteria.

When the plan file is written, simply finish your turn: the workflow checks it and moves to the next phase.
